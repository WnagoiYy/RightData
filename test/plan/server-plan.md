## 1. 定位与术语

RightData 按新项目开发。旧项目及 `test/doc/` 中的设计资料用于参考，不直接搬迁代码，也不自动沿用旧方案的全部功能和实现。

旧数据与配置按实际可迁移程度处理：先评估，能够通过直接导入或简单转换正确迁入的就迁入，无法适配或成本较高的跳过并在新实例重新配置。不为此开发旧接口兼容层、旧格式运行模式或专门的兼容性迁移体系；迁入内容须符合新系统的数据、权限、密码及引用规则，记录已迁入与跳过范围并保留旧实例。本次不执行数据迁移。

内网服务端提供稳定、通用的数据与文件能力，负责身份认证、权限校验、数据库操作及数据一致性。客户端负责页面、交互、业务功能组织，以及 Excel 等格式的解析与生成，以减少常见界面和展示需求对服务端部署的影响。

### 1.2 术语

| 术语 | 本项目定义 |
| --- | --- |
| 数据集 | 一个 DuckDB 业务数据库文件 |
| 数据文件 | 统一管理的 DuckDB 文件，包括业务库、系统库及备份文件 |
| 数据表 | 数据集库文件中的表 |
| 数据 | 数据表中的记录 |
| 普通文件 | 附件、素材等由文件管理接口管理的文件 |
| 全量导出 | 按权限和查询条件取得完整结果，由客户端生成 Excel 等文件 |

全量导出与整库下载分别授权、分别处理。全量导出不意味着取得库内全部表或超出当前用户权限的数据。

## 2. 公共服务能力

- 接口方式：统一采用 HTTP REST API，不引入 GraphQL。服务端 HTTP 路径统一以 `/api` 为前缀，覆盖登录、业务操作、上传下载、日志、健康检查、客户端更新及接口文档等入口；文档及其配套静态资源也位于此前缀下。具体资源路径、请求与响应结构、错误码及版本约定在接口设计阶段细化。
- 登录与身份认证：登录入口放在 RightData 客户端，客户端调用服务端登录接口；服务端验证身份，支持业务会话恢复、续期及注销，不另行开发后端业务管理页面或登录页面。客户端“记住登录”默认勾选，由应用自行保存会话恢复凭据，不关联 Windows 系统凭据；组网身份与业务会话分离，具体认证协议和有效期在开发时细化。
- 系统配置数据管理：报表、看板、H5、动态菜单及资源绑定、查询定义等共享配置，统一纳入 `system.duckdb` 配置表的增删改查；布局、样式等可保存为 JSON。服务端限定可操作的表和字段并校验权限，客户端负责编辑与展示。保存查询定义不等于执行查询，实际取数仍通过受控查询接口。看板与通报的动态菜单查看及配置预览按第 2.4 节执行。
- 权限校验：服务端在执行操作时校验权限，客户端界面控制不能替代服务端授权。
- 数据访问：查询和写入遵守用户的数据访问范围；行列权限的具体模型另行细化。
- 库级权限：整库下载、备份管理和数据库密码获取属于库级管理能力，不能由普通数据查询权限推导。
- 最终校验与事务：服务端对字段、类型、操作目标和写入内容进行最终校验，并负责需要原子完成的数据库操作。
- 登录前连通性与实例识别：在 `/api` 前缀下提供不依赖业务登录的最小探测能力，返回服务标识、稳定实例标识、接口兼容信息及就绪状态，不暴露业务数据、配置或凭据；完整运维详情仍受权限控制。实例标识在普通重启后保持不变，结合受信连接身份用于核对直连和中转是否指向同一服务，不能只凭客户端提供的实例 ID 授权。客户端所有网络请求由 Tauri Rust 层统一接管，优先内网直连；同一服务实例上的有效业务会话不因路径切换而失效。具体探测路径与身份验证机制在开发时细化。

### 2.1 运行保障

运行保障确定为服务端的公共能力，统一用于查询、SQL 工作台、导入、导出、备份及其他数据操作，并复用各能力章节中的事务、权限和执行约束。

| 能力 | 服务端职责 |
| --- | --- |
| 日志与审计 | 记录操作人、时间、目标、执行结果、耗时及错误，提供访问、查询、导入和导出等服务端日志查询，以及客户端导出结果的接收能力；中转日志默认由客户端本机保存和查询；密码、凭据等敏感内容不写入日志 |
| 后台任务管理 | 对导入、导出、备份等耗时操作提供任务标识及状态、进度、结果查询；客户端断线不等于任务取消 |
| 超时与取消 | 控制 SQL 和任务执行时间，支持取消并处理事务回滚；已提交成功的操作不能再标记为取消 |
| 重复请求与失败恢复 | 防止网络重试导致重复导入或写入；服务重启后检查未完成任务并核实提交结果，不盲目重新执行写操作 |
| 资源限制 | 控制并发任务、查询结果量、上传大小、内存及临时磁盘占用，避免单个操作耗尽服务资源 |
| 健康检查与启停 | 检查系统库、存储及服务是否就绪；停止服务时妥善处理运行中任务并关闭数据库 |
| 临时数据与日志清理 | 清理过期上传、导出结果、错误明细及日志，遵守文件归属、任务状态和数据保留规则 |

对客户端提供或复用日志查询、任务状态与结果查询、任务取消及健康检查接口；其他控制由服务端内部实现。超时、并发、容量、清理周期、保留期限、任务执行方式及恢复步骤在开发时细化，当前不预设固定参数。

查询日志覆盖通用查询生成的 SQL 和受控 SQL 执行，并标明工作台、报表、看板、通报或大屏等调用来源。导出日志区分服务端取数结果与客户端文件生成和保存结果；中转连接失败等事件由中转进程在本机采集，不能假定内网服务端已收到请求。中转明细默认不集中回传，客户端导出结果统一回传，需回传的离线事件恢复后补报，具体字段和保留参数在开发时细化。

中转日志记录节点自动登记与离线、请求选路、连接和链路变化、转发结果及失败原因，不因此增加设备审批、节点管理或中转权限管理。节点标识和路径信息用于排错关联，不能作为业务用户身份或权限的依据；Token、设备密钥及其他凭据不得写入日志。

客户端事件接收与补报：

- 在 `/api` 前缀下提供客户端事件接收接口，至少接收客户端导出文件生成及保存的成功、失败、取消等结果，关联导出任务或操作标识，统一纳入导出日志查询。
- 接收事件时校验认证、原服务实例、用户与任务归属、事件类型和状态，不能允许客户端改写其他用户的日志。离线事件由原归属身份补报，不因后来登录了另一账号而改变事件用户。
- 按稳定事件标识幂等接收并返回确认；重复请求返回已接收状态，不重复入账。分别保留事件发生时间与接收时间，按阶段及顺序处理延迟或乱序事件，不用较早的进度覆盖最终结果。
- 客户端在收到确认前持久化保留待发送事件，恢复连接或重启后补报。日志传输与业务操作解耦，上报失败不改变已经完成的导出结果；服务端尚未收到报告时标记客户端阶段未知，不推断本地文件已经保存。
- 服务端直接执行的阶段与“客户端报告”分开记录，客户端报告不反向覆盖服务端查询或任务的实际状态。本项不要求接收所有本机中转明细，补报也不等于上传业务结果文件。

### 2.2 接口文档

采用 GoFrame 自动生成的 OpenAPIv3 文档及 Swagger UI，提供接口说明与调试入口。客户端“接口管理”直接嵌入该 Swagger UI，不单独开发接口文档和调试页面。文档页面属于随服务提供的开发工具页面，不扩展成后端业务管理前端；所需静态资源随服务提供，适配内网使用。[GoFrame 接口文档与自定义鉴权说明](https://goframe.org/docs/web/api-document-openapiv3)

访问规则：

- 用户必须已登录，并具有“接口文档查看”权限。
- 文档页面 `/api/swagger` 和文档数据 `/api/api.json` 均由服务端鉴权，相关文档子路径也纳入保护；不能仅隐藏客户端菜单或只保护页面。
- 未登录返回未认证状态，无权限返回禁止访问状态；直接访问地址不能绕过检查，也不跳转到不存在的后端登录页面。
- 文档访问复用客户端到内网服务端的受控连接方式。文档会话失效、用户退出或权限被撤销后，后续请求不得继续访问。
- 在线调试调用的业务接口仍校验用户的业务身份和操作权限；接口文档查看权限不授予业务数据读写权限。

登录与文档访问衔接：

1. 用户在 RightData 客户端登录，由服务端签发登录凭据。
2. 用户从客户端的“接口管理”入口打开嵌入的 Swagger UI；客户端集成层负责让文档页面及 `/api/api.json` 请求携带有效认证，不假定普通链接导航会自动附带客户端 Token。
3. 嵌入页面如需使用浏览器会话，则由已登录客户端申请短期、一次性的文档访问票据。服务端验证票据后建立与原用户关联、仅用于文档访问的受保护会话，避免另做网页登录页；长期登录 Token 不放入 URL。

浏览器会话使用安全 Cookie，具体票据交接、有效期、Cookie 属性及客户端内嵌方式在开发时细化。票据签发、兑换和后续文档请求均校验登录状态及文档权限，票据不写入普通日志。客户端登录界面尚未完成时，开发人员可使用接口调试工具调用登录接口取得凭据，不因此开放匿名文档访问。

### 2.3 客户端中转与业务会话

中转与后台运行方案已确认，客户端具体行为见 [client-plan.md](./client-plan.md) 第 5.5 节。服务端按以下边界配合：

- 同一安装包交付 Tauri 界面和独立 Rust 网络服务，组网、发现、节点选择与转发由客户端网络服务负责，不要求内网 Go 服务端承担公网发现或业务中继。
- 网络服务启用且能直接连接本服务实例的客户端自动登记为可用中转节点；设备身份自动生成，与业务会话分离。不设置设备审批、邀请码、节点管理或中转权限，节点使用也不要求双方登录同一业务账号。
- 服务端按每个业务请求携带的用户 Token 校验身份及实际操作权限，不以中转节点身份、节点用户或来源节点地址代替用户认证，也不把会话绑定到某个中转节点。当前请求经 A 节点、下个请求经 B 节点时，同一有效业务会话继续使用。
- 登录、会话恢复和最小连通性探测遵守各自的接口认证规则，可在尚未业务登录时经中转到达；不要求先取得业务 Token 才能建立中转通路。最小探测能力供节点判断本实例是否可达、就绪，并保持既定的信息披露范围。
- 中转范围限定为配置的同一内网服务实例及其 `/api` 接口，不向请求方开放任意内网目标。固定转发目标不构成额外的设备或中转访问授权。
- 任务、上传、导出结果和幂等状态由服务端管理，通过用户、任务或操作标识识别，不绑定中转连接。同一操作的后续请求可经不同节点到达；写入结果不明时查询原结果，不能因换节点重复执行。
- 关闭窗口、退出登录、完全退出客户端界面或注销 Windows 均不停止已启用的后台网络服务。业务注销仅撤销相应业务会话，不撤销设备身份、不停止节点，也不影响其他用户经该节点访问；节点是否可用由内网可达性与本机服务启停决定。关机、休眠或失去内网连接后节点离线，由客户端重新选路。
- 公网发现与协调服务默认不承载业务数据；公网业务中继另行授权，并由 Rust 网络服务在传输层执行限制，覆盖 iroh 首次连接、重连和回退。该授权与内网节点免审批、免额外中转权限的规则分开处理，不替代服务端业务鉴权。

节点健康、延迟和负载用于客户端逐请求选路；服务端无需为此新增节点管理界面或中转授权接口。正在进行的单次请求及流式传输保持稳定，链路失效后的恢复继续遵守服务端的任务、幂等和下载约定。节点与路径事件进入中转日志，具体字段、汇总方式及保留参数按日志方案细化。

### 2.4 动态菜单与看板、通报预览

查看入口与窗口方案已确认：配置人员可以在配置页面或独立客户端窗口预览；普通用户只能通过有权限的动态菜单进入，在客户端主窗口查看并可全屏，不提供普通用户的独立窗口或浏览器分享查看入口。具体窗口交互见 [client-plan.md](./client-plan.md) 第 3.2 节。

- 动态菜单统一支持报表、看板和通报资源，通过资源类型与资源标识保存绑定，以及菜单名称、层级、顺序和访问权限。相关数据复用系统配置管理能力，不另建浏览器页面或通报门户。
- 普通查看时，服务端校验目标资源已保存、已启用，并存在当前用户有权访问的有效菜单绑定，同时检查资源及实际数据权限。校验基于服务端保存的绑定和权限，不相信客户端声明“已点击菜单”；直接提交资源标识或访问内部路由不能绕过检查。
- 配置预览要求相应资源的配置权限，可以预览未挂载或停用的资源；普通用户不能通过预览入口绕过动态菜单访问规则。页面内预览与独立窗口预览适用相同权限，独立窗口不形成新的用户身份或授权范围。
- 未保存的编辑内容只用于配置人员预览，不隐式持久化、不覆盖正式配置，也不影响普通用户查看已保存内容。预览需要查询数据时，仍由服务端校验当前配置人员的目标、参数、查询定义及数据权限，不因提交内容来自编辑器而免检。
- 预览和普通查看复用通用查询与受控 SQL 查询定义，遵守第 3.7、3.9 节的执行边界，不为窗口形式新增统计接口。配置权限不自动授予全部数据权限或 SQL 工作台权限。
- 各客户端窗口复用同一业务会话和 Rust 网络服务；服务端继续按实际请求用户校验权限。参数和筛选条件随各窗口请求分别传入，不在服务端会话中保存一份会被其他窗口覆盖的全局筛选状态。
- 业务注销撤销相应会话，各窗口后续请求不得继续访问；资源停用、菜单授权或配置权限变化后，后续查看、预览及取数请求按当前状态重新校验。客户端负责关闭或清理失去访问权限的窗口内容，网络中转服务继续运行。

主窗口、全屏及独立预览窗口的创建、布局、复用和关闭由客户端负责。服务端不以关闭窗口作为自动取消后台任务的依据，也不因多窗口而要求重复登录。已实现的菜单、资源查看及预览接口见 `server/README.MD` 和 OpenAPI。

### 2.5 客户端更新分发与本地状态

更新与本地状态方案已确认，客户端行为见 [client-plan.md](./client-plan.md) 第 5.6 节。主程序和管理界面采用完整安装包，获取顺序为“内网直连 → 内网客户端提供的更新接口 → 公网更新源”，不提供管理界面资源独立更新；另行确认的大屏业务资源独立发布需求见第 2.6 节。

- 内网服务端在 `/api` 前缀下提供客户端版本信息及完整更新包获取能力，包括识别适用平台与架构、版本及文件、验证签名和完整性所需的信息。首版面向 Windows 10、Windows 11 的 x64 客户端，具体路径、字段和发布存放方式在开发时细化。
- 内网客户端的独立 Rust 网络服务提供受控更新获取接口，为外网客户端转取内网的版本信息和安装包；复用既有组网及节点选择，不增加节点审批或更新中转权限。版本与文件由内网更新源管理，不要求每个节点维护独立发布配置。
- 内网直连及节点路径均无法获取时，客户端才使用预置或配置的公网更新源；内网正常返回无更新不构成公网回退条件。公网更新源分发同一发布体系的客户端更新文件，与公网发现及业务中继分开，不因此开放内网业务数据。
- 同一版本的更新文件及校验信息保持一致，节点转发不修改安装包。客户端在切换来源或恢复下载时核对文件身份，并在安装前校验签名和完整性；具体下载与续传实现后续细化。
- 更新包同时交付管理界面程序与 Rust 网络服务。服务端只提供更新信息与文件，客户端安装器负责本机升级和服务启停；大屏资源按单独版本分发，不用于替换客户端管理界面或原生程序。
- 草稿和界面偏好属于客户端本地状态，按实现便利程度选择保留，不要求服务端为此新增草稿同步或恢复服务。本地草稿恢复不自动改写服务端配置，已保存数据及配置继续以服务端为准。

服务端已实现 Windows x64 完整包发布、版本查询、下载与停用，协议见 `server/README.MD`；客户端选路、安装器和安装升级逻辑仍由客户端实施。

### 2.6 数据大屏资源分发

已确认保留“数据大屏”，支持独立、不定期开发后将资源上传服务端，由客户端下载最新资源并接入后端数据。随后确认继续补齐可实现的旧版能力，服务端已实现最小静态包协议 v1；HTML 与 React 均交付构建后的静态 ZIP，详细契约见 [大屏协议](../../server/docs/screen-v1.md)，客户端入口与容器实现配合 [client-plan.md](./client-plan.md) 第 3.5 节。

- 建议统一接收构建完成的静态网页资源包，简单 HTML 与 React 等项目使用同一种交付格式。服务端保存成品，不在生产环境执行上传项目的构建脚本，不承担 Node.js 页面渲染服务。
- 大屏标识、查询绑定及权限存入共享配置，版本、入口、文件清单与哈希、容器接口版本和发布指针存入系统库，原始 ZIP 存入实例 `screens/`。版本上传与列表使用 `/api/v1/screens/{id}/versions`，发布和回退使用 `/{id}/publish`，下载使用 `/{id}/versions/{version}/download`。
- 上传与发布须有相应管理权限；验证清单、入口与文件完整性，限制解包路径和解压规模，不能让资源包覆盖服务端程序或其他资源。版本文件保持不可变，当前发布版本单独指向完整有效的包，支持切回上一可用版本。
- 客户端查询当前有权限访问的已发布版本，经内网直连或内网节点中转下载；版本检查和资源获取不走客户端程序更新的公网兜底源。包的完整性和容器兼容性确认后才切换，不以部分上传或下载成功作为发布完成。
- 大屏展示需要的筛选、汇总及复杂统计复用通用查询和受控 SQL 查询定义，不为每个大屏编写专属 Go 统计代码。服务器维护资源与数据源或查询定义的绑定，按当前用户校验资源及实际数据权限，资源包自身声明不构成授权。
- 大屏通过客户端容器提供的受控取数接口访问数据，Rust 网络服务携带业务凭据访问后端；资源包不持有数据库密码或登录 Token。普通展示默认只读取数，不获得任意 SQL、任意网络目标或原生系统访问能力。
- 修改图表、布局和已有取数配置可重新发布大屏包，不要求重发客户端安装包或服务端程序；需要新增容器接口、数据执行能力或数据库扩展时，再评估相应程序升级。大屏缓存仅是资源缓存，不引入离线业务库。

资源包管理属于大屏内容发布；客户端主程序和管理界面的整体更新继续按第 2.5 节执行。服务端协议已实现并通过专项测试，客户端容器与完整端到端验收单独记录；该实现不包含具体业务大屏设计或旧数据迁移。

## 3. 已确认的数据与文件能力

### 3.1 数据集管理与数据库运维

客户端菜单名称确定为“数据库运维”，对应旧项目的“数据备份”菜单。该入口统一管理 DuckDB 文件，包括连接管理自动生成的库文件、在此上传的库文件、系统库和生成的备份文件。

服务端提供文件列表与信息查询、创建、删除、上传、密码查看、生成备份文件及下载能力：

| 能力 | 行为 |
| --- | --- |
| 列表与信息 | 展示文件名、类型、来源、大小、时间及关联连接；密码提供显示入口。具体字段在开发时细化 |
| 创建与登记 | 新建加密 DuckDB 库后登记文件及密码；连接管理自动生成的文件也进入同一份文件管理记录，不形成另一套独立文件清单 |
| 上传 | 在“数据库运维”中上传库文件并提供其密码，服务端校验有效性后登记；文件就绪后可由连接管理选择使用 |
| 显示密码 | 有权限的用户可查看完整文件密码。默认隐藏，按需显示；服务端校验密码查看权限并记录操作，不把明文密码写入日志或普通文件列表响应 |
| 生成备份文件 | 对选定数据库生成一致性备份，默认沿用源库当时的密码；备份完成后作为独立文件登记，保留来源与生成时间，并在同一页面管理 |
| 下载文件 | 下载所选文件；使用中的库通过一致性快照交付，已完成的备份直接下载。下载文件配合该文件密码即可在支持其存储格式的 DuckDB 环境使用 |
| 删除 | 删除指定文件前检查权限、连接引用和占用状态；不能使现有连接无提示地失效，具体处理流程在开发时细化 |

文件记录统一关联实际文件及其密码，连接记录引用文件标识。上传或创建采用独立标识处理同名文件，不能仅凭文件名覆盖使用中的库。备份保存生成时对应的密码，源库后续改密不修改历史备份的密码记录。

系统库也纳入“数据库运维”管理，但按系统管理权限控制查看密码、备份和下载；运行中的 `system.duckdb` 不允许通过普通文件删除或上传覆盖操作替换，也不自动作为普通业务数据集开放。

客户端提供管理界面、文件选择、密码显示和下载保存。服务端负责文件登记、密码管理、有效性检查、备份一致性及存储管理。库恢复、改密和文件切换的执行步骤在开发时按已有权限与一致性边界细化。

### 3.2 数据表管理

服务端提供建表、删表、表与字段信息查询，以及表结构修改。

新增字段、修改字段类型等属于表结构操作；修改某行的字段值属于记录操作。客户端提供表结构设计和管理界面，服务端验证并执行结构变更。具体支持的结构变更范围及限制另行确定。

### 3.3 数据管理

服务端提供记录的新增、删除、查询、修改。基础查询支持字段选择、筛选、排序和分页。

客户端负责表格展示、编辑交互及操作组织；服务端负责权限、类型和数据约束校验，以及实际读写。需要共同成功或共同失败的批量操作，由服务端统一执行事务。

看板、H5 通报及报表所需的取数与聚合统一使用第 3.9 节的通用查询和受控 SQL 能力，不按页面类型分别开发取数接口。

### 3.4 批量导入

导入职责分工：

1. 客户端解析 Excel 等源文件，完成预览、字段映射和标准 CSV 转换。
2. 服务端接收 CSV 文件，提供导入接口。
3. 服务端校验目标表、字段、类型和权限，执行批量写入并返回导入结果。

服务端不承担 Excel 解析和排版相关职责。客户端转换不能替代服务端的最终校验。

上传完成与导入完成是两个状态。涉及清空后导入、条件替换、去重等写入语义时，由服务端统一处理事务，不能依赖客户端串联多个独立请求来保证原子性。

CSV 格式、导入模式、结果与重试规则采用第 3.8 节“导入导出数据约定”，具体接口字段在开发时细化。

### 3.5 文件管理

服务端提供普通文件、附件和素材的上传、下载、列表、元信息修改、替换与删除，并负责存储、归属及访问权限。

客户端负责文件选择、预览、编辑和保存。DuckDB 文件统一通过第 3.1 节的“数据库运维”能力处理。

### 3.6 全量导出

全量导出复用数据查询能力：服务端按权限和条件提供完整结果，客户端负责生成 Excel，处理样式、列宽、格式并保存。

- 完整结果包括所有符合条件且有权访问的记录，不局限于当前页面。
- 取数采用第 3.8 节的分块、流式传输约定。
- 同一次全量导出使用一致的数据快照，由服务端保证各批次来自同一结果。
- 服务端不承担 Excel 文件生成和样式处理。

### 3.7 SQL 工作台

服务端通过 HTTP REST API 提供 SQL 语句执行能力。客户端负责 SQL 编辑、参数输入与结果展示；服务端负责校验、授权、执行及结果返回。请求指定数据集、SQL 文本及需要绑定的参数，数据集由服务端解析到受控数据库连接。

安全要求包括 SQL 注入防护和 SQL 执行权限控制：

- 参数化：普通增删改查接口及 SQL 工作台中的外部业务值通过参数绑定传入，不以字符串拼接或模板替换混入 SQL。表名、列名和排序方向等不能作为值参数绑定的部分，使用授权元数据校验、允许值映射及正确的标识符引用。
- 独立授权：SQL 执行接口需要专门授权，并校验目标数据集和实际操作权限。查询、数据写入和结构变更分别判断，不能将工作台访问权限等同于全部数据库操作权限。
- 完整校验：通过语法解析和执行策略检查语句类型、引用对象及函数等，不能只靠关键字黑名单、正则或判断是否以 `SELECT` 开头。多语句请求必须逐条校验，不能夹带未授权操作；具体支持的语句集合在接口设计阶段细化。
- 数据权限：SQL 工作台不得绕过数据访问范围及行列权限；无法可靠施加相应约束的执行方式应拒绝，不能仅检查数据集 ID 后直接执行任意 SQL。
- 能力限制：工作台 SQL 不得自行访问未授权数据库、系统凭据、任意服务器文件或网络资源，也不得自行安装加载扩展、改变安全配置。数据库挂载及必要的执行配置由服务端管理。
- 执行隔离：不可信 SQL 需要最小操作系统权限及进程、容器或操作系统沙箱等隔离；DuckDB 的外部访问限制等配置作为补充，不能单独视为完整安全边界。具体隔离形式在实施阶段确定，并与受控导入、备份等操作的执行环境区分。
- 执行约束：设置超时、取消、结果量及资源限制，记录调用者、目标数据集、操作类别和执行结果等必要审计信息；日志及错误响应不得泄露密码、凭据或敏感参数。具体限额在实施阶段细化。

原始 SQL 本身是工作台允许提交的执行内容，参数化只能保护其中的参数值；不能把“使用参数绑定”当作对整段用户 SQL 的授权或安全保证。[OWASP SQL 注入防护](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)、[DuckDB SQL 执行安全](https://duckdb.org/docs/2.0/operations_manual/securing_duckdb/overview)

### 3.8 导入导出数据约定

本节作为后续开发的默认方案，具体请求字段、错误码、批次大小、容量及超时在开发时细化。接口继续采用 HTTP REST API；客户端处理 Excel，服务端提供通用的数据导入与完整取数能力。

#### 3.8.1 数据格式

| 内容 | 默认约定 |
| --- | --- |
| CSV 基本格式 | UTF-8 无 BOM；逗号分隔；首行为字段名；客户端统一输出 LF 行结束符 |
| 字段与表头 | 客户端完成字段映射；表头与提交的列定义一致且不重复；已有表以服务端表结构为准，新建表使用显式提交并经校验的结构，不靠抽样自动推断类型 |
| 引号与转义 | 双引号包围需要转义的值，内部双引号写为两个双引号；保留字段内的逗号、换行和有效空白 |
| 空值 | 未加引号的 `\N` 表示 `NULL`；`""` 表示空字符串；实际文本 `\N` 写为 `"\N"`，不自动把空字符串转换成空值 |
| 数值与布尔值 | 数值使用十进制文本、小数点为 `.`、不含千分位；布尔值使用 `true` / `false`；大整数与定点小数在客户端转换过程中保持精度 |
| 日期与时间 | 日期使用 `YYYY-MM-DD`；无时区时间戳保留原有日期时间语义；带时区时间戳统一为 UTC、使用带 `Z` 的 ISO 8601 表示；小数秒精度按字段类型保留 |
| 文本与复杂类型 | 文本不自动去空格、转换为数值或丢弃前导零；复杂类型只有在定义了明确的无损表示后才允许导入，否则返回不支持的类型错误 |

服务端显式配置 CSV 方言和类型，关闭自动推断，采用严格解析，不静默跳过坏行。空值规则对应显式设置 `nullstr` 为 `\N`、`allow_quoted_nulls = false`；不能依赖解析器默认值。[DuckDB CSV 参数说明](https://duckdb.org/docs/2.0/data/csv/overview#parameters)

#### 3.8.2 上传、校验与提交

1. 客户端解析源文件、完成预览和映射，生成 CSV，并保留 CSV 记录与原文件行号的对应关系。
2. 通过文件上传接口传输 CSV 字节，服务端校验大小和完整性并返回上传标识。文件不以 Base64 塞入 JSON；上传标识绑定上传者，服务端不接受客户端指定的任意本地路径。
3. 客户端提交上传标识、目标数据集和表、字段定义或映射、导入模式及本次操作的幂等标识。服务端返回导入任务标识，客户端可查询进度与最终结果。
4. 服务端在暂存区进行完整的格式、字段、类型及约束校验；执行写入前再次校验权限和目标表结构。
5. 在同一个目标数据库事务中执行实际写入及必要的删除、合并或建表。全部成功才提交；任何错误或提交前成功受理的取消都回滚，不留下部分业务数据。[DuckDB 事务说明](https://duckdb.org/docs/2.0/sql/statements/transactions)

默认不提供“出错后自动跳过坏行并提交其余行”的隐式行为。错误信息包含可定位的 CSV 逻辑记录序号、字段及原因，客户端映射回源文件；错误明细数量受控，并明确是否截断，避免返回整个文件。

#### 3.8.3 导入模式与结果

| 模式 | 行为 |
| --- | --- |
| 追加，默认 | 向目标表追加记录，保留现有数据 |
| 全表替换 | 用户明确选择后，在同一事务内清空数据并导入；保留目标表结构和约束，不通过删表重建实现 |
| 按条件替换 | 服务端验证结构化条件及其权限范围，在同一事务内替换匹配数据；导入记录必须落在该范围内 |
| 按键合并 | 指定经过校验的唯一键，匹配时更新指定字段，不匹配时新增；未参与更新的字段保留原值 |
| 按键跳过已有记录 | 指定经过校验的唯一键，已存在的键跳过，其余新增，并返回跳过数量 |

按键操作要求键值非空、目标匹配唯一；同一导入批次出现重复键时默认报错，不依赖文件顺序决定覆盖结果。缺失列与显式 `NULL` 分开处理：新增记录的缺失列按表默认值及约束处理；更新时未提供的列保持原值。所有模式均校验实际受影响记录的读写权限；全表替换要求相应的全表管理权限，空文件的替换请求默认拒绝。具体模式参数在开发时细化。

导入结果至少区分待处理、执行中、成功、失败和已取消；成功结果给出已提交的新增、更新、删除及跳过数量，失败或取消结果明确是否回滚。上传成功、校验通过、事务提交成功是不同阶段，只有提交成功才能表示数据已导入。

同一用户、数据集和幂等标识对应同一次导入；重复请求返回已有任务或结果，参数不同则拒绝复用。幂等结果与实际提交保持一致。客户端断线后先查询原任务，不能另建操作重复入库；提交已经完成时，取消请求不能把结果改为已取消。

#### 3.8.4 全量导出

- 客户端提交数据集、字段、筛选及排序等查询条件，服务端生成导出任务，并校验完整的数据访问权限；任务执行和下载时均检查权限，权限失效时拒绝继续提供结果。
- 服务端在同一一致性快照中执行查询，分块写入受控临时结果文件，生成完成后提供下载。网络下载阶段不持续占用数据库读事务，也不通过对持续变化的表反复执行普通分页来拼接结果。
- 默认使用 UTF-8 NDJSON 传输：首条记录描述字段名、类型及顺序，中间记录承载分块的行数组，末条记录标明完成状态与总行数。批次序号和文件完整性信息用于核验，不把连接关闭当作导出成功。
- `NULL` 使用 JSON `null`，空字符串仍为空字符串；64 位及更大整数、`DECIMAL` 使用十进制字符串传输。日期与时间遵守上述类型语义。其他类型必须有明确的序列化规则，不能在不提示的情况下丢失精度或改成展示文本。
- 同一导出任务对应不可变结果，下载重试或续传读取同一文件。结果过期后重新创建任务，不能把新旧快照的数据拼在一起。
- 客户端流式读取并生成 Excel，按字段类型写入单元格；大整数、精确小数及带前导零的编号需要保留精度。用户文本写为文本单元格，不因以 `=` 等字符开头而自动变成公式。
- 超出单个 Excel 工作表容量时由客户端拆分工作表或文件，并明确告知拆分；不能静默截断。Excel 生成失败不代表服务端查询失败，客户端可复用有效的导出结果重试生成。

导入暂存文件、导出结果和错误明细均设置容量、有效期及清理机制，并校验归属与访问权限。文件大小、分块大小、任务时限、并发量及续传字段在开发时按实际数据量细化；当前不预设未经验证的固定限额。

### 3.9 查询与聚合

采用“通用查询与基础聚合 + 受控 SQL 兜底”，共用第 3.7 节已确认的 SQL 执行能力，为报表、看板、H5 及其他客户端功能提供通用取数服务。

| 能力 | 范围与实现方式 |
| --- | --- |
| 明细查询 | 字段选择、条件筛选、排序、分页及总条数，由通用查询接口提供 |
| 基础聚合 | 求和、计数、去重计数、平均值、最大值和最小值，由通用查询接口提供 |
| 分组统计 | 按地区、类别、月份等一个或多个维度分组汇总，由通用查询接口提供 |
| 报表辅助查询 | 去重筛选选项、全量结果汇总和下钻后的明细，复用通用查询接口 |
| 复杂分析 | 同比环比、累计、移动平均、排名、占比及多表关联，按复杂程度使用通用查询或受控 SQL |
| 特殊业务计算 | 多层子查询、复杂条件计算及自定义统计规则，使用受控 SQL 兜底 |

通用查询接收目标数据集和表、字段、筛选条件、分组、聚合、排序及分页等结构化条件，由服务端校验并生成 SQL。全量结果汇总针对符合条件且当前用户有权访问的全部数据，不能只统计当前分页。下钻后的目标查询同样校验权限。

服务端返回通用数据结果，客户端负责表格或图表展示、布局、颜色和交互。复杂分析优先使用 DuckDB 的聚合与窗口函数，不为每种图表单独编写计算逻辑。[DuckDB 聚合函数](https://duckdb.org/docs/2.0/sql/functions/aggregates)、[DuckDB 窗口函数](https://duckdb.org/docs/2.0/sql/functions/window_functions)

SQL 复用与权限边界：

- SQL 工作台面向有专门权限的用户，按第 3.7 节校验其提交的 SQL 及实际操作权限。
- 报表、看板和 H5 运行时优先提交通用查询条件；复杂查询可保存为查询定义，由使用者提交“查询定义 ID + 参数”，服务端读取定义并执行只读取数。普通使用者不因此获得 SQL 工作台权限。
- 查询定义通过系统配置数据的增删改查保存，并控制其编辑权限；保存定义不等于授权执行，运行时仍校验当前用户对查询定义及实际数据的访问权限。
- 通用查询、查询定义执行与 SQL 工作台共用参数绑定、权限检查、超时、取消、资源限制、结果转换及审计能力；具体接口入口是否合并在开发时细化。
- 行列权限必须对参与计算的原始数据生效，包括关联或子查询引用的数据源，不能在聚合后才追加权限过滤。无法可靠落实权限的复杂 SQL 应限制或拒绝执行；只读设置不能替代数据权限控制。
- 运行时 SQL 同样遵守第 3.7 节的语法校验、能力限制和执行隔离要求，不因来源是已保存配置而自动放行。

查询表达结构、支持的算子及时间计算参数等在开发时细化。多数统计需求通过客户端或查询配置调整；需要新增数据库扩展或执行能力的需求，仍须评估服务端变更。

## 4. 数据库密码、存储格式与系统初始化

### 4.1 已确定的方案

- 所有数据集使用 DuckDB 2.0。
- 使用 DuckDB 原生数据库加密，通过 `ENCRYPTION_KEY` 提供密码，采用默认的 AES-256-GCM。
- 一个数据库对应一个数据库密码。创建时可设置密码或生成高强度密码。
- 对用户的可移植交付形式为“一个 `.duckdb` 文件 + 该库密码”，不要求另外携带 `.key` 文件，也不引入 RightData 专有的外层文件加密格式。
- 备份与下载默认沿用该库密码，不为每份备份另建一套用户需要管理的密码。
- 新建库直接使用 DuckDB 2.0 的最新存储格式，即 `STORAGE_VERSION 'latest'`；不提供旧版存储格式兼容方案。

下载后的库文件可在支持该存储格式和原生加密的 DuckDB 环境中凭密码打开，不依赖原 RightData 服务实例。这里的可移植性不包含旧版 DuckDB 兼容承诺。

### 4.2 密码管理边界

- 服务端需要在重启后自动打开数据库，因此必须保护性保存可恢复的数据库密码，不能像登录密码一样只保存不可逆哈希。
- 文件密码记录在系统库的数据文件或凭据管理表中，以可恢复的受保护形式保存，供有权限的用户查看。系统库自身的密码同样记录入表，并按第 4.4 节保留独立于系统库的受保护启动凭据。
- 密码不得写入普通日志、错误回显或无关响应。
- 拥有完整库文件和密码即可访问库内全部数据；服务端的行列权限不会随文件自动限制外部使用者。
- 修改数据库密码按重新加密生成新库处理。已有备份与已下载副本仍使用生成时的密码，不会因在线库改密而自动变化。

### 4.3 文件一致性

备份和下载必须交付完整、一致、可单独打开的库文件。服务端负责正确处理正在执行的写入与 WAL，不能仅复制正在写入的主文件并假定其包含所有已提交数据。具体快照、关闭或切换流程在实施设计阶段确定。

### 4.4 系统数据库自动初始化

服务端启动时自动检查并初始化系统数据库，文件名固定为 `system.duckdb`，默认位于 `server/data/system.duckdb`。使用 DuckDB 2.0、最新存储格式及原生密码加密。

首次初始化流程：

1. 确认是尚未初始化的新实例，生成高强度随机数据库密码，并先安全持久化系统库之外的启动凭据。
2. 使用该密码创建 `system.duckdb`。
3. 自动创建系统所需数据表和必要的初始记录，范围包括系统管理、配置管理、开发与运维、日志，以及数据文件与密码管理等。具体表名、字段、索引和初始数据在开发时确定。
4. 将系统数据库自身登记到数据文件管理表，将自动生成的密码记录到相应数据表，并记录初始化及结构版本。
5. 初始化成功后开放服务；有权限的管理员可以在“数据库运维”中管理系统库、查看密码、生成备份并下载。

后续启动复用已有系统库和密码，按结构版本执行必要的建表或迁移。初始化应支持重复启动、并发启动保护和失败恢复；不能每次启动都重新生成密码、覆盖表或重置用户数据。

系统库密码不能只存在于它自身的加密数据表中，否则重启后无法先解锁系统库。因此，服务端在系统库之外的受保护凭据存储中保留可用于解锁的启动凭据，解锁后再读取系统表中的文件密码记录。两处信息应保持一致；存储介质、保护方式及改密更新步骤在开发时细化。这属于服务端内部启动管理，用户下载单个库文件使用时仍只需要该文件和密码。

已有实例出现库文件缺失、密码缺失、解锁失败或迁移失败时，应明确报告并停止相关服务，不得自动换密码或生成空系统库掩盖故障。系统库备份仍须满足可独立打开的一致性要求；整实例恢复时，应恢复匹配的启动凭据，或由已知的系统库密码重新登记启动凭据，不要求用户额外携带专用密钥文件。

## 5. 客户端与服务端的计算边界

查询与聚合按第 3.9 节的方案实现，客户端与服务端遵守以下职责边界：

- 决定从数据库取得哪些数据的筛选、关联、分组、汇总和全量排序，由服务端执行并校验权限。
- 普通报表的全量汇总、去重筛选选项和下钻取数，统一复用服务端通用查询能力。
- 客户端可以对已完整取得的授权结果进行格式化、单位换算、绘图和适量衍生计算。
- 当衍生计算结果还要参与全量筛选、排序或分页时，需要在服务端查询阶段完成。
- 看板与 H5 的页面布局、编辑和交互由客户端负责；复杂分析及特殊业务计算通过通用查询或受控 SQL 查询定义完成。

本计划记录已确认能力及其边界。接口、DDL、可调容量默认值及实现限制已在服务端说明中补充；未支持能力仍保留为后续实施范围，不以基础实现替代完整计划验收。

第 2.6 节的大屏独立资源分发协议已按后续确认实施，验收见 `test/results/server-screen-validation.md`。旧数据迁移、具体业务大屏内容及真实跨网验收不在此次服务端协议交付中。
