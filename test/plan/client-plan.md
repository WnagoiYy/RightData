## 1. 迁移目标与现状

将旧项目 `K:/WorkSpace/CompleteProjects/RightDataPlatform/frontend/` 中已实现的前端功能基本完整迁入本项目 `client/` 的 Tauri 客户端，保持原有样式和交互习惯。客户端可复用旧前端的组件、样式及资源；服务端按 [server-plan.md](./server-plan.md) 的新方案开发，客户端适配新的通用 API，不要求照搬旧后端接口。

只交付客户端业务界面，不另外部署浏览器业务前端。看板和通报只能在客户端打开，不提供浏览器分享查看入口。

已检查的现状：

- 旧前端采用 React、TypeScript、Vite 和 Ant Design，已有 SQL 编辑器、报表、看板编辑器、通报源码编辑与预览等能力。
- 本项目 `client/` 已有 Tauri 2、React、TypeScript、Vite 基础工程，目前仍为模板示例。本轮只读取现状，不修改该工程。
- 后续沿用现有前端技术体系完成迁移，不因使用 Tauri 而重写界面技术栈；Rust 层承担必要的网络、本地文件及桌面集成能力。
- 客户端源码、依赖、配置及资源位于 `client/`；部署内容位于 `deploy/`；测试和报告位于 `test/`，不新增根目录文件或第五个顶层目录。

## 3. 界面保留与必要适配

### 3.1 样式与交互

- 保留旧前端的配色、字体、间距、侧栏、表格、表单、弹窗、图表和编辑器样式，不主动进行视觉重设计。
- 新增日志页面及桌面功能沿用既有组件和样式，不引入另一套设计风格，不新增重复大标题或常驻功能说明。
- 用户明确要求的菜单更名、移动、分享入口删除及新增功能可以调整对应内容；不借迁移改动无关页面。
- 保留已有看板截图、通报 PNG/JPEG 生成及文件导出能力，保存动作适配客户端。取消在线分享不等于取消已有图片导出。
- 具体窗口尺寸、缩放和显示适配在开发时检查；以相同视口下的旧页面作为样式对照。

### 3.2 通报与看板

查看入口与窗口方案已确认：配置人员在配置页面编辑和预览，可主动打开独立客户端预览窗口；普通用户只能通过有权限的动态菜单进入，在主窗口查看，不提供独立窗口入口。

| 场景 | 入口与行为 |
| --- | --- |
| 配置看板或通报 | 从“配置管理／看板管理”或“配置管理／通报配置”进入，保留编辑及页面内预览 |
| 配置人员独立预览 | 从配置或编辑页面主动打开 Tauri 独立预览窗口，可移动至其他屏幕并全屏 |
| 普通用户查看 | 从“数据工作台”下有权限的动态菜单进入对应资源，在主窗口内容区展示 |
| 普通用户全屏 | 在当前查看页面进入全屏，隐藏导航和无关操作，按 Esc 返回；不创建独立窗口 |

动态菜单与配置权限：

- 看板和通报沿用统一的菜单挂载机制，配置人员选择资源、设置菜单位置并分配访问权限。普通用户不经配置管理页面查找内容，也不能借独立预览路由绕过菜单访问规则。
- 普通查看使用已保存、已启用且挂载到当前用户可访问菜单的配置；未挂载或停用的资源不作为普通用户查看入口，有相应配置权限的人员仍可预览。
- 编辑器中未保存的修改只用于配置人员预览，不自动写入服务端或影响普通用户已保存的查看配置。
- 菜单可见性、资源访问、配置预览及实际数据权限由服务端校验。配置预览不自动扩大数据权限，不能仅靠隐藏按钮或客户端路由限制访问。

页面与窗口：

- 主窗口查看、页面内预览和独立预览复用相同的渲染与取数能力，保留原有样式。独立预览窗口只提供筛选、刷新、全屏及图片导出等必要操作，不放入整套管理侧栏。
- 资源名称显示在现有导航或窗口标题中，不重复增加内容区大标题和说明。通报源码、参数、数据源配置、历史版本及已有图片导出能力纳入迁移。
- 独立预览窗口共享当前业务登录和统一 Rust 网络服务，无需再次登录；不在窗口 URL 或通报脚本中传递登录 Token，也不扩大通报脚本的原生访问能力。
- 新开预览时带入当前参数和筛选条件，之后各窗口分别维护查看状态，不相互改写。每个资源默认复用一个独立预览窗口，重复打开时激活已有窗口，避免不断新建。
- 将旧 `window.open` 浏览器入口按使用场景改为主窗口查看或配置人员的独立预览，不保留浏览器分享查看入口。

窗口生命周期：

| 用户操作 | 窗口与业务状态 | 后台网络服务 |
| --- | --- | --- |
| 关闭独立预览窗口 | 仅关闭该窗口，不退出登录、不关闭主窗口 | 继续运行 |
| 关闭主窗口 | 主窗口隐藏到托盘，已打开的独立预览窗口继续展示 | 继续运行 |
| 退出登录 | 关闭独立预览窗口，清理各窗口业务数据，主窗口返回登录页 | 继续运行 |
| 完全退出 | 关闭全部客户端窗口和托盘；记住登录按第 5.2 节处理 | 继续运行 |

会话或相应权限失效后，相关窗口停止取数并清理无权继续展示的内容。关闭预览窗口停止该窗口的刷新，不将窗口关闭等同于取消已经提交的服务端后台任务。

取数与运行边界：

- 通报与看板取数复用服务端的通用查询及受控 SQL 查询定义，不为每个页面另建统计接口。
- 通报引用的脚本、字体及其他运行资源随客户端或受控资源机制提供；文件引用适配新的文件 API，不能继续依赖旧网站同源的 `/h5-runtime/` 路径。
- 通报中的可编辑 HTML/脚本与客户端原生能力隔离，通过受控消息取得授权数据，不能直接调用任意 Tauri 命令、文件路径或网络目标。嵌入 Swagger 同样只获得文档与业务调试所需的受控访问，不附带本地系统权限。按目标平台验证隔离方式，不把一个 iframe 标签视为全部安全边界。[Tauri 能力与权限边界](https://v2.tauri.app/security/capabilities/)

### 3.3 接口管理

- 嵌入服务端 `/api/swagger`，由其加载 `/api/api.json`；两者及文档子路径均须登录并具有文档查看权限。
- 复用客户端登录状态和 Tauri Rust 层的统一连接，文档页面、静态资源、`/api/api.json` 及在线调试请求均由该层接管，按服务端计划完成认证衔接；不另做文档登录页。
- 文档在线调试仍校验实际业务权限。界面只展示 Swagger 提供的功能，不复制旧接口管理页的自定义文档编辑和调试实现。
- 旧接口管理还包含启停、IP 白名单等配置；Swagger 本身不替代这些管理策略，如仍有业务需求，单独确认后归入相应配置能力。

### 3.4 数据导入导出与数据库运维

- 客户端解析 Excel、完成预览及字段映射，生成约定的 CSV；服务端负责最终校验与事务写入。
- 客户端通过通用查询或导出任务取得完整结果，在本地生成 Excel；不再依赖旧服务端生成 Excel 的接口。
- 数据库运维使用“DuckDB 文件 + 对应密码”的方案，移除旧“导出解密 key”流程，不沿用旧备份密钥管理界面。
- 统一适配文件选择、流式传输、保存位置和进度反馈，区分上传完成、数据库提交完成、结果下载完成及本地文件生成完成。
- 服务端后台任务不因客户端断线或关闭窗口而自动取消；重新连接后通过任务标识查询实际状态，具体恢复交互在开发时细化。

### 3.5 数据大屏：独立开发与资源发布

已确认需求：保留“数据大屏”，按业务需要不定期单独开发；大屏资源上传服务端，有更新时客户端下载最新资源；运行时接入同一服务端业务数据。大屏不要求并入客户端主工程共同发布。以下是建议落地方案，HTML 或 React 的开发选型及管理入口尚未最终确认。

建议采用“独立项目开发 → 构建静态资源包 → 上传并发布版本 → 客户端拉取并展示”。复杂交互大屏优先考虑 React + TypeScript + Vite，简单展示可直接使用 HTML、JavaScript 和 CSS；两者统一交付静态网页资源包，客户端无需知道源码采用哪种框架。React 项目先构建，再上传产物，不让客户端现场编译 JSX/TSX 或安装 npm 依赖。Vite 可生成静态部署产物，并通过相对资源路径适应不同加载位置。[Vite 构建与资源路径](https://vite.dev/guide/build#relative-base)

| 部分 | 建议职责 |
| --- | --- |
| 独立大屏项目 | 编写图表、布局、交互及参数，通过统一的数据调用接口取数；可使用模拟数据独立开发 |
| 服务端 | 保存大屏记录、版本、资源包及数据源绑定，提供上传、发布、版本检查和下载，复用现有查询与权限能力 |
| 客户端大屏容器 | 检查更新、下载与校验资源，在隔离环境中展示；提供当前用户上下文、受控取数、全屏及刷新等能力 |

建议的资源与发布约定：

- 以 ZIP 上传一个完整版本，包含入口 HTML、JS、CSS、图片、字体等，以及大屏标识、版本、入口文件、所需容器接口版本等清单信息。依赖随包提供，不依赖现场访问公网 CDN，不在包内包含数据库密码、业务 Token 或固定服务端地址。
- 源码与客户端主工程分开组织，但项目内新增源码仍放在 `client/` 的独立子目录；发布文件与服务端存储归属 `server/`，部署和测试分别归属 `deploy/`、`test/`。本次不创建大屏工程或样例文件。
- 服务端按大屏标识保存不可变版本及当前发布版本，上传、校验和预览后再发布；保留可回退的上一版本，不覆盖正在使用的版本文件。建议在“资源管理”下设置“大屏资源”管理入口，现有“数据大屏”用于展示，最终菜单位置另行确认。
- 客户端进入大屏时检查服务端当前发布版本，发现更新则下载到新的版本目录，完整校验并确认容器兼容后切换。已打开的大屏可后台检查和预下载，刷新或重新进入时切换，避免演示中途强制重载；具体检查时机在开发时细化。
- 更新失败时保留上一可用版本；首次下载失败则显示无法加载。缓存的是程序资源，不代表可脱离服务端获得数据权限或继续展示过期业务结果。
- 大屏资源通过内网直连或既有内网节点中转从业务服务端获取，不自动套用客户端安装包的公网兜底来源。主程序和管理界面仍随完整安装包更新，大屏业务内容按本节单独发布；新增容器能力才需要评估客户端程序升级。

建议的数据接入与运行方式：

- 提供一个轻量的大屏调用接口或 SDK：大屏提交查询定义标识和参数，由客户端容器转交 Rust 网络服务访问后端并返回结果。普通查询复用结构化查询能力，复杂取数复用已保存的受控 SQL 查询定义，不让每个大屏处理登录、中转或连接地址。
- 服务端维护大屏与可用查询定义或数据源的绑定，并按当前用户、资源及数据权限校验；资源包声明的数据需求不能直接成为授权。普通展示默认只读取数，发布大屏的权限不等于对全部数据的访问权限。
- 在独立的网页运行环境中加载资源，与管理界面的 DOM、样式、存储及原生能力隔离。可采用经验证的 sandbox iframe 或隔离 WebView，具体机制在开发时验证；受控消息只开放所需取数能力，不提供任意 URL 请求、文件路径或 Tauri 命令执行。
- 数据与网络请求均经过容器和 Rust 网络服务，大屏脚本不直接获得登录 Token。不能因资源已下载到本机就把它视为与客户端主程序同等可信；按实际窗口、命令和消息来源落实权限边界。[Tauri 能力与权限](https://v2.tauri.app/security/capabilities/)
- 普通用户建议从已有“数据大屏”菜单进入，在主窗口展示并支持全屏；多个大屏时仅展示有权限的资源。配置人员从资源管理中预览，不新增浏览器分享入口。普通用户不借大屏容器取得配置或原生系统权限。

### 3.6 旧数据与配置处理

已确认按可迁移程度处理旧数据与配置：先检查旧账号、角色、菜单、报表、看板、通报、数据文件及普通文件，能够通过直接导入或简单转换正确迁入的就迁入；不匹配或代价较高的跳过，在新实例重新配置，不勉强搬迁。

不为此开发旧接口兼容层、旧配置运行模式或专门的兼容性迁移体系。迁入内容必须符合新系统的数据、权限、密码和资源引用规则，不把无法识别的配置强行当作有效数据。实施时记录已迁入与跳过的范围，迁入前验证副本，保留旧数据，不自动覆盖或删除旧生产实例。本次不执行任何数据迁移。

| 日志 | 记录范围 |
| --- | --- |
| 访问日志 | 保留访问审计能力，记录用户、接口、时间、请求结果及耗时等 |
| 中转日志 | 默认持久化在本机，由 Rust 网络服务记录节点登记与离线、连接、请求选路、转发结果、传输量及失败原因；页面默认查询本机记录，不自动汇总全部中转明细到服务端，不另建节点管理或审批页面 |
| 查询日志 | 覆盖通用查询生成的 SQL，以及受控 SQL 执行，包括工作台提交和已保存查询定义的执行；标明报表、看板、通报、工作台等来源，记录目标、结果、耗时、行数及错误等 |
| 导入日志 | 关联导入任务，记录目标、模式、处理状态、提交结果、成功或失败数量及错误摘要；区分校验通过与入库成功 |
| 导出日志 | 关联导出任务，记录服务端取数、传输和客户端生成文件的阶段及结果；客户端导出结果统一回传服务端，断线时暂存并在恢复后补报；服务端取数成功不能直接代表本地 Excel 已保存成功 |

“两种 SQL 执行”在日志中按“通用查询生成 SQL”和“受控 SQL 执行”区分，同时保留调用来源，以便分别查看工作台操作和页面运行时取数。

日志页面沿用旧访问日志的筛选、列表与详情交互，具体字段在开发时细化。服务端日志由服务端校验查询权限；本机中转日志通过受控本机调用读取，沿用相应日志菜单访问规则，不要求中转服务先业务登录才能写日志。SQL 和参数展示按敏感信息规则处理，不记录数据库密码、登录凭据或整份业务结果。请求标识、任务标识及执行标识用于关联不同阶段，避免同一次操作被误认为多个独立结果。

日志存放与补报方案已确认：

- 访问、查询、导入及服务端导出阶段的日志由服务端记录；中转明细默认保存在本机。离线补报针对需要回传的客户端事件，至少包含客户端导出结果，不将全部本机中转日志自动转为平台日志。
- 客户端将文件生成及保存的成功、失败、取消等结果提交到服务端接收接口，关联原导出任务或操作标识，并保留“客户端报告”来源。未收到客户端结果时，服务端不能把取数成功推断为本地文件保存成功。
- 待回传事件先持久化到本机队列，再异步发送。网络恢复后自动补报，应用重启后继续发送尚未确认的事件；收到服务端确认后才移出待发送队列，不因超时而认为已上报成功。
- 使用稳定事件标识支持去重，保留事件发生时间与服务端接收时间，重复补报不得重复计数，延迟到达的旧事件不得覆盖较新的最终结果。
- 事件绑定原服务实例、用户和任务，补报仍校验归属；需要原用户认证时待其恢复登录后发送，不套用后来登录的其他用户身份。回传日志不阻塞正常导出，也不将一次失败的回传改成导出失败。
- 本机日志轮转、队列容量、重试间隔、保留时间及异常处理在开发时细化，避免无限增长或静默丢弃待补报事件。本项不新增全平台中转日志汇总要求。

## 5. 连接与运行边界

### 5.1 登录与连接设置

- 首版采用单一业务环境，不提供多环境列表、切换登录或多环境会话管理。
- “连接设置”集中配置中转服务器地址和内网服务端地址。公网中转服务器默认承担发现与协调，不能将其地址直接当作业务服务端地址；公网业务中继单独授权，按第 5.5 节执行。
- 使用预置连接配置，普通用户无需每次输入地址；修改后由应用保存，重启后保留。
- 登录前即可打开“连接设置”，登录后仍可从客户端进入。自动连接与恢复均失败时弹出该设置窗口，展示简短原因和重试操作；同一次故障不反复弹窗，已有成功路径时正常自动切换不打断用户。
- 登录页沿用原有样式，保留账号、密码和“记住登录”，不增加环境选择器或要求用户选择“内网客户端／外网客户端”。
- 内网直连与外网中转是同一服务实例的两条连接路径。切换路径时继续当前有效业务会话，不要求重新登录。
- 修改服务端地址后重新识别目标实例。确实更换了服务实例时，清除旧实例的页面数据和权限上下文，重新登录；不向新目标发送旧实例的登录凭据。这属于修改连接目标，不扩展成多环境登录功能。

### 5.2 记住登录

- “记住登录”默认勾选，用户可以取消。勾选后保存应用自己的会话恢复凭据，下次启动先建立可用连接并验证服务实例，再向服务端恢复登录。
- 凭据由应用的 Rust 层自行管理和持久化，不使用 Windows 凭据管理器、DPAPI 或 Windows 登录账号绑定，不依赖操作系统凭据体系。
- 保存用于恢复业务会话的应用凭据，不保存用户密码；凭据不放入页面脚本可直接读取的普通 Web 存储，不传给通报脚本。具体本地存储与保护方式在开发时细化，并遵守不关联系统凭据的要求。
- 未勾选时，登录凭据只保留于当前客户端会话，完全退出客户端后不恢复该次登录；取消记住登录时清理已有持久化业务会话凭据。
- 网络暂时不可达时保留有效的本地会话信息并尝试恢复连接；服务端明确返回凭据过期、撤销或失效时，回到登录页。恢复后以服务端当前权限为准。
- 主动退出登录清理本地业务会话凭据，联网时同时注销服务端会话；断网清理本地记录不等于已完成服务端注销。有效期、续期和撤销的具体机制在开发时细化。
- 组网使用应用自动生成并持久化的独立设备身份，与业务会话分开保存，不依赖业务登录或 Windows 登录凭据。设备身份用于建立网络连接和关联日志，不作为设备审批或中转访问授权；退出业务登录、完全退出界面均不清除该身份或停止后台中转。

### 5.3 所有请求统一由 Tauri 接管

所有对外网络请求由 Tauri 集成的 Rust 网络层统一接管，独立 Rust 网络服务负责实际连接、路由和转发，界面通过本机通信调用该服务；React 页面不直接访问业务服务端或中转服务器。内部统一处理连接选择、身份凭据、超时、取消、请求标识及流式传输；内网可直达时，网络服务直接请求服务端，外网时经中转访问同一服务端。该服务的运行不依赖 Tauri 窗口或业务登录状态，本机通信方式在开发时细化。

覆盖范围包括登录、会话恢复、通用查询、SQL 执行、配置管理、日志、任务、上传下载、图片与文件资源，以及 Swagger 页面、文档 JSON 和在线调试请求。探测、发现、中转接入、客户端更新检查和下载，以及大屏资源检查、下载和取数也由 Rust 网络层发起。客户端随包提供的静态资源及经过校验的大屏缓存资源在本地加载。

普通接口通过受控调用接入网络层；Swagger、通报及图片等浏览器资源请求通过受控资源代理或协议适配接入同一网络层。选择 Tauri 本身不会自动接管 WebView 的全部网络请求，迁移时必须处理旧 `fetch`、资源 URL、浏览器跳转和嵌入页面请求，并验证没有绕过统一路径的直发请求。具体适配机制在开发时细化。[Tauri 前端调用 Rust](https://v2.tauri.app/develop/calling-rust/)

对服务端的请求统一使用 `/api` 前缀，由网络层处理地址拼接；客户端页面路由不受此前缀约束。中转只转发到本应用配置的同一内网服务实例，不接受页面或外部请求提供的任意目标地址，也不开放通用内网代理；这属于转发范围，不引入节点或使用者的中转权限审批。通过中转访问时，业务后端地址由实际发起后端请求的内网侧解释，不能把内网节点的回环地址当作外网客户端本机地址。

### 5.4 内网探测与无感切换

以“能否直接连接并验证预期服务实例”判断当前是否可走内网直连，不以本机 IP 网段、网卡名称、Ping 成功或单纯端口连通作为依据。内网客户端与外网客户端是当前连接状态，不是需要用户手动设置的固定身份；网络服务启用且能直接连接预期内网服务时，即自动登记为可用中转节点，不再检查额外中转资格。

连接顺序：

1. 启动时读取预置或已保存的连接设置，由 Rust 网络层先对内网服务端发起短时、无业务凭据的应用层探测。
2. 通过专用连通性接口检查服务类型、稳定的实例标识、接口兼容性和就绪状态，并验证受信的服务身份。符合预期且可用时，优先选择内网直连。
3. 直连发生网络连接失败或超时时，自动发现可用内网节点，使用独立组网身份建立连接，再经该路径验证同一服务实例；不要求业务登录、设备审批或中转访问授权。客户端与内网节点之间优先建立直连，公网业务中继须另行授权，禁止静默回退。
4. 有可信可用路径后，才恢复已保存的业务会话或提交用户输入的账号密码。获取登录接口的连接不能依赖尚未取得的业务登录凭据，避免循环依赖。
5. 直连和中转均无法提供可用连接时，再弹出“连接设置”；用户处理完成后重新探测，不反复要求输入账号密码。

持续运行时监听网络变化，并在中转期间后台复查直连。直连恢复且经过稳定性确认后，新请求优先切回直连；采用退避和防抖避免频繁切换，探测时限及频率在开发时细化。正在进行的成功传输不因发现更优路径而强制中断；连接中断后的恢复遵守任务及文件续传约定。

错误分类与切换规则：

- 连接超时、连接中断等网络故障可以触发选路；收到密码错误、会话失效、权限不足或 SQL 执行错误时，按业务结果处理，不以换路径重试规避。
- 服务可直接响应但尚未就绪、接口不兼容等情况按对应服务故障处理，不简单认定为“外网”；仅靠更换路径不能修复同一服务端故障。
- 实例或受信身份不匹配的路径不发送业务凭据、不承载业务请求。两条路径必须指向同一经过验证的实例，不能仅凭返回的名称或实例 ID 文本视为可信。
- 写操作结果不明确时先查任务或幂等结果，不能因切换链路而更换操作标识重复提交；服务端后台任务不会因客户端断线而自动取消。
- 业务数据、共享配置和最终权限以服务端为准，本项不引入离线业务库及离线写入同步。

### 5.5 中转与后台运行

本项已确认：同一安装包交付 Tauri 界面和独立 Rust 网络服务，采用内嵌 iroh 组网。网络服务注册为 Windows 服务，独立于窗口、托盘、业务登录和用户桌面运行，不要求用户另行安装组网软件。

设备接入与节点发现：

- 设备身份自动生成并持久化，首次使用自动接入发现与协调服务；不设置设备审批、邀请码、人工登记或中转权限配置。
- 采用“可用即登记”：本机网络服务已启用且能够直接连接预期内网服务实例，就自动登记为该实例的中转节点，其他客户端可自动发现和使用。登记只用于维护可用节点信息，不是授权审批。
- 节点资格取决于内网服务可达性及本机网络服务是否启用，与界面是否打开、业务用户是否登录或所属账号无关。失去内网连接或服务停止时自动退出可用节点集合，恢复后重新登记。
- 外网客户端发现可用内网节点后即可尝试建立中转，不校验额外的设备权限、用户中转权限或账号关联，不要求请求方和节点登录同一业务账号。
- 不新增节点管理、设备管理或中转审批页面。节点登记、可用性变化和转发事件记入现有“系统日志／中转日志”。

请求选路与业务认证：

- 本机可直连服务端时优先直连；需要中转时，每个请求独立从可用节点中选择健康、延迟较低且负载合适的节点。不绑定某个用户或业务会话必须使用同一节点，前一个请求可经 A 节点、下一个请求经 B 节点。
- 单次请求及正在进行的流式传输保持其连接稳定，不因出现更优节点而中途换路；节点或链路失效后再按操作语义恢复。同一后台任务的后续状态查询、下载等独立请求可使用其他节点。
- 业务请求携带请求用户自己的 Token，由内网服务端校验身份及实际业务权限；中转节点只负责转发，不使用节点用户的业务身份代替请求用户，不增加一层中转权限校验。
- 登录、会话恢复和最小连通性探测可以在尚未业务登录时经中转访问，由服务端按对应接口规则处理，避免先登录才能建立登录通路的循环依赖。
- 重试及切换节点保留请求、任务和幂等标识。写入结果未知时先查原操作结果，不因换节点重复提交；上传下载按各自任务或续传约定恢复。

后台启停与客户端行为：

- 普通客户端按需启动网络服务；自动登记成为可用中转节点后，默认启用后台服务开机启动，界面不随之自动弹出。
- “连接设置”提供本机网络服务的启动、停止及开机启动开关，不扩展为远端节点管理。用户显式停止服务后暂停本机网络与中转，不由连接重试立即重新启动；重新启用后恢复探测和登记。关闭开机启动只影响下次启动，不自动停止当前服务。
- 关闭窗口、退出登录和完全退出客户端界面都不停止网络服务。业务会话清理只影响当前用户自己的业务调用，不清除设备身份，也不影响为其他客户端转发请求。

| 用户操作 | 界面与登录状态 | 后台中转 |
| --- | --- | --- |
| 点击主窗口关闭按钮 | 主窗口隐藏到托盘，保持当前登录；独立预览窗口继续展示，关闭独立预览只关闭该窗口 | 继续运行 |
| 退出登录 | 清除当前用户的业务会话及各窗口业务数据，关闭独立预览窗口，主窗口返回登录页 | 继续运行，使用独立设备身份 |
| 完全退出 | 关闭全部客户端窗口和托盘；已勾选的记住登录可保留，未勾选则清理本次业务会话 | 本机网络服务继续运行 |
| 锁屏或注销 Windows | 界面按系统行为处理 | 已启用的网络服务继续运行，内网可达时继续中转 |
| 关机、休眠 | 客户端不可用 | 节点离线，其他客户端重新选路 |

公网发现与公网业务中继：

- 公网发现服务器负责设备发现、地址交换和连接协调；业务优先在客户端之间直接传输，再由内网节点访问服务端。公网发现与公网业务中继分别管理，允许发现不等于允许公网承载业务流量。
- 需要通过公网中继传输业务数据时另行明确授权，未获授权不能因客户端之间无法直连而自动回退到公网中继。该要求只针对公网业务中继，不为内网节点增加接入或使用权限。
- iroh 的默认中继建连或回退行为必须在实际传输层受上述策略约束，覆盖首次连接、重连及路径变化；不能仅依赖“直连优先”的界面说明。授权范围及传输层实现细节在开发时细化。

### 5.6 更新与本地状态

本项已确认：客户端主程序和管理界面采用完整安装包更新，默认从内网获取，外网客户端优先通过内网客户端提供的更新接口获取，以上路径均不可用时才从公网更新源获取。不提供主程序和管理界面的资源独立更新；用户另行明确要求的大屏业务资源按第 3.5 节单独发布。

更新来源与获取顺序：

| 优先级 | 获取路径 |
| --- | --- |
| 1 | 直接访问内网更新源，取得版本信息和完整安装包 |
| 2 | 无法直连时，通过可用内网客户端的 Rust 网络服务所提供的更新获取接口，转取内网更新源的版本信息和完整安装包 |
| 3 | 内网直连及内网客户端提供的路径均无法完成获取时，使用预置或配置的公网更新源 |

- 检查更新和下载均经过统一 Rust 网络层，复用既有内网探测与节点选择，不要求用户手动选择内外网。内网客户端通过更新接口提供文件转发，是否缓存已下载的完整安装包在开发时按需要确定，不要求另建文件分发系统。
- 更新来源切换以连接或文件获取不可用为依据；内网源正常返回“无更新”时正常结束检查，不因此继续到公网寻找其他版本。跨来源继续同一次下载时须核对版本与文件标识，不能混合不同安装包的片段。
- 内网、节点转发和公网来源遵守同一套发布版本、更新包签名与完整性校验规则，校验通过后才能安装；保留手动安装完整更新包的方式。Tauri 提供更新包签名机制，具体接入与安装流程在开发时细化。[Tauri 更新插件](https://v2.tauri.app/plugin/updater/)
- 公网更新源仅用于已发布客户端程序的兜底分发，与公网发现、业务中继分别处理。本项已允许在前两种路径不可用时获取公网更新，不因此允许公网承载业务请求或数据；不向公网更新源发送内网业务 Token、数据库密码等凭据。
- 客户端管理界面资源、Tauri 程序与独立 Rust 网络服务随同一版本安装包交付，沿用已确认的 NSIS 升级方式，安装时协调服务停止、替换及恢复。共享业务配置继续由服务端管理和读取；大屏资源采用单独发布机制，不用于替换客户端管理界面或原生程序。

草稿与偏好：

- 重启后的未保存草稿和界面偏好按实现便利程度保留：能以较低成本可靠恢复的就保留，恢复复杂或跨版本不兼容的可以不保留，不作为首版交付的强制要求，也不再列为待确认事项。
- 不为此引入复杂的草稿同步、跨版本恢复或离线业务数据库；本地恢复的草稿不自动覆盖服务端已保存配置，仍需用户执行保存。
- 连接设置、独立设备身份，以及已勾选“记住登录”的会话恢复凭据，继续按第 5.1、5.2、5.5 节持久化，不因草稿和偏好可选保留而改为可选。服务端已保存的数据及配置不受本地草稿是否保留影响。
